# Codex版の使い方

## Claude版との違い

Geminiによる英日翻訳、用語集、数値・引用の検証、日本語PDFの配置は共通です。段落の役割・段またぎの結合・記号対応を補正するCLIを、Claude CodeからCodex CLIへ切り替えます。Claude版と同じ翻訳補助として、Codexが用語集を点検し、検証後も英語のまま残った段落だけを訳し直します。全文校正は行いません。

## Windows PCでの準備

1. Python 3.11以上を導入し、ZIPを展開して `setup.bat` を実行します。
2. [公式のCodex CLI案内](https://developers.openai.com/codex/cli/)からCLIを導入します。デスクトップアプリのログインだけで、別途導入したCLIも必ずログイン済みになるとは限りません。
3. ターミナルで `codex login` を実行し、ご自身のChatGPTアカウントでログインします。`codex login status` で確認できます。[公式の認証説明](https://learn.chatgpt.com/docs/auth)
4. `翻訳アプリCodex.bat` を開きます。配布されたCodex版では通常の `翻訳アプリ.bat` でもCodexが選ばれます。
5. ローカル画面でご自身のGemini APIキーを登録し、送信条件に同意します。Codexによる構成の整理（構造補正）は必須で、選択するチェックボックスはありません。
6. PDFを選び、ファイル名・ページ数・サイズを確認して、出力形式を選びます。選択だけでは翻訳は始まりません。**「翻訳を開始」**を押し、生成後に日本語版または英日交互版をダウンロードします。

構造補正が使えない場合（CLI未導入・未ログイン・API認証や独自接続先の検出など）は、開始時に理由と直し方を表示し、「構成の整理なしで続けますか?」と確認します。同意した場合だけ、構造補正なし（`--no-structure`）で続けます（Web方針B）。処理途中で構造補正がスキップされた場合は、結果欄に「構成の整理は行われませんでした: 理由」を表示します。Codex APIは使いません。

終了コード7（日次上限）・9（APIエラー・開発用の予算上限）・12（一部の段落が英語のまま）の場合は、結果欄の**「この段落だけ再翻訳する」**ボタン1つで再試行できます。保存済みの同じPDFを `--retry-failed` で再実行するため、再添付は不要です。日次上限の場合は解除後に押してください。再試行用のチェックボックスはありません。

利用者のAPIキーや認証ファイルは配布ZIPに含めません。Geminiキーの保存・削除は共通のWeb設定画面を使います。送信先の異なる版へ切り替えたときや、送信条件が変わったときは同意を確認し直します。

## 翻訳の補助

- 既定オンです。用語集の点検では、題名・要旨（最大900文字）・用語集をOpenAIへ送ります。問題段落の補正では、対象段落の原文・現在の訳・失敗理由と関連用語を送ります。
- 返された補正は、Geminiの訳と同じタグ・数値・英語残りの検証を通ったものだけ採用します。
- Web画面で「Codexに翻訳の補助をさせない」にチェックすると止められます。CLIでは `--no-assist`。構造補正は引き続き有効です。
- `[assist] max_calls_per_doc = 4` は構造解析1回を含む枠です。補助は用語集1回・段落補正最大2回。入力に対応する結果をキャッシュし、同じ内容の再試行では再利用します。認証確認の `login status` は補助回数に含みません。
- 結果欄に補助の採用件数とスキップ理由を表示します。API認証・独自接続先では補助も実行しません。Codex CLIは文書の作業フォルダから隔離した一時ディレクトリで実行します。

## コマンドから使う

```powershell
python -m readable input.pdf --structure-provider codex --mode both --out out
```

アプリ内部で呼ぶ構造補正CLIは `codex exec` です。認証確認は `codex login status` を使い、ChatGPT契約ログインを確認できる場合だけ実行します。

構造補正を使わず配置を確認する場合：

```powershell
python -m readable input.pdf --structure-provider codex --no-structure --translator dummy --out out
```

dummyの訳文は原文の意味とは関係のない配置確認用です。実翻訳の品質を示すものではありません。

## 設定・保存・制約

- `config.toml` の `[codex] model`、`timeout` を指定できます。既定は `gpt-5.6-sol` と180秒。開発のサブエージェントは指定のGPT-6.1 Solを使用していますが、2026-10-02の実CLIでは `gpt-6.1-sol` がChatGPT認証で拒否されました。CLIで使えるモデルは各自の環境で確認してください。指定モデルが失敗しても別モデルやAPI認証へ自動変更しません。
- `[structure] provider` は `claude | codex | none`。`--structure-provider` を指定するとその起動で優先されます。
- Codex版の既定作業領域は、共通workルートの `codex/` です。Claude版の同時処理とキャッシュ書込みが衝突しないよう分けています。
- Codex構造解析は一時ディレクトリで実行し、最終JSONだけを共通処理へ返します。CLIが無い、認証を確認できない、タイムアウト、不正応答の場合は、CLI内部では警告して簡易解析を使います。Web画面では開始前の利用可否確認と、途中でスキップした理由の結果表示を行います。
- PDFの文章は翻訳にGoogleへ、構造補正の抜粋と有効にした翻訳補助の対象データはOpenAIへ送ります。使用量・扱いは利用者の契約と各サービスの条件に従います。
- OCR文字層が付いたスキャンPDFは対応対象です。画像だけのPDFに文字認識を新規実行する機能はありません。OCR誤りや配置の重なりは出力確認が必要です。
- 図・表とその中の文字はそのまま残します。和訳ホバー注釈はClaude版と同じく既定オフです。必要な場合は `config.toml` の `[table_terms] annotations = true` にすると、透明な和訳注釈を付けます（`annotation_style = "invisible"`）。注釈を付ける場合は図表内の文字の翻訳にもGeminiを使います。対応するPDFビューアではホバーやコメント一覧で和訳を読めます。本文での図表用語の英語併記は各ページの初出だけで、色・下線は付けません（`color = ""`、`gloss_first_only = true`）。
- 結果は最新1件だけ保持します。翻訳キャッシュは直近3文書ぶんを保持し、日次上限で止まった文書は再開用に残します。詳細は `README.md` と `docs/WEBAPP.md` を参照してください。
