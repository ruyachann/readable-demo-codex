# ローカル Web アプリ (README に統合する文)

### C. `翻訳アプリ.bat` (ブラウザで操作)

最初に `setup.bat` を 1 回実行し (フォルダ内の `.venv` にライブラリを入れます)、あとは `翻訳アプリ.bat` をダブルクリックします。ブラウザが開き、初回は設定画面 (Gemini API キーの登録・プライバシーへの同意) が出ます。詳しくは `docs/INSTALL.md`。

PDF を 1 つドラッグ&ドロップ (または選択) すると、ファイル名・ページ数・サイズを表示します (この時点では翻訳は始まりません)。出力形式を選んで **「翻訳を開始」** を押すと変換が始まり、完了後に日本語版・交互対訳版をダウンロードでき、PDF のプレビューも新しいタブで開けます。

- 出力 (日本語版 / 交互対訳版 / 両方) を選べます。構成の整理 (Claude / Codex) は常にオンで、チェックはありません。使えないとき (未ログイン・未インストール・API キー/ゲートウェイの検出) は、「翻訳を開始」を押した時に理由と直し方を表示し、「構成の整理なしで続けますか? (品質が下がる場合があります)」で同意した場合だけ、構成の整理なし (`--no-claude` / `--no-structure`) で続けます。途中でスキップされた場合は、結果欄に「構成の整理は行われませんでした: 理由」を表示します。
- 終了コード 12 (一部の段落が英語のまま)・7 (日次上限)・9 (API の回復不能なエラー) のときは、結果欄に「この段落だけ再翻訳する」ボタンが出ます (12 は「英語のまま残った段落: N件」付き、7 は「明日16時以降に押すと続きから」)。保存してある同じ PDF を `--retry-failed` で再実行し、再添付は不要です。元の PDF は再翻訳が終わるまで消えません。再試行時にも構造補正の利用可否を確認し、復旧済みなら補正を有効に戻します。使えない場合は理由と続行確認を再表示します。Codex版の導入と認証は `docs/CODEX.md` を参照してください。
- 進捗 (抽出 → 構造解析 → 翻訳 → PDF 生成) とログ末尾が表示され、失敗時は終了コードに応じた日本語の説明が出ます (例: 7 = 日次上限、翌日に「この段落だけ再翻訳する」を押すと続きから再開)。
- **処理は 1 ファイルずつ、結果は最新の 1 件だけ**保持します。新しい翻訳を始めると前回の PDF は削除されます (必要ならダウンロードしてから)。翻訳中に別のファイルを入れると、「中止して新しく始めますか?」と確認します。アプリを終了して再起動すると、前回の結果は消えます。
- 翻訳の途中経過 (キャッシュ) は `work/` に、最近使った 3 文書ぶんだけ残します (日次上限で止まった文書は、続きから再開できるよう消しません)。
- **PC への影響は最小**です。標準ライブラリだけで動き、追加インストール (setup.bat 以外)・常駐・レジストリ変更・管理者権限は不要です。127.0.0.1 だけで待ち受けるため外部から接続できません。**bat のウィンドウを閉じると完全に終了**します。
- 起動ごとに変わるトークン付き URL で開きます。ブラウザのタブを閉じてしまったら、bat を閉じて起動し直してください。
- 直接起動: `python -m readable.webapp [--port 8765] [--no-browser]` (ポート使用中なら空きを探します)。
- API 仕様は `docs/API.md`。このアプリは公開サーバとしての利用を想定していません。

プライバシーは README の注意と同じです (Gemini 無料枠は入出力が学習に使われうる)。画面にも注意を表示しています。

### 構成の整理の結果・ログ・中止 (確認のしかた)

- **構成の整理が使われなかったとき**は、結果欄に黄色の枠で表示します。「構成の整理は行われませんでした: 理由」(使えない・スキップ)、「構成の整理の結果は全部/一部使われませんでした: N件を反映、M件は不採用」(Claude/Codex の結果を検証で不採用にした)。コア側の件数は、ログ 1 行 `[構造] 反映 N 件 / 不採用 M 件 : 理由` か `render_report.json` の `structure` (`accepted`/`rejected`/`reason`) から読みます。
- **ログの全文**は `work/web_jobs/<id>/job.log` にも保存します (画面は末尾 20 行のみ)。API キーは `***` に置き換えます。次の翻訳を始めるとジョブごと削除されます。
- **中止を試すには**: (1) PDF を選んで「翻訳を開始」を押し、処理中に結果欄の「中止」を押す。(2) 状態が「失敗 (終了コード 130)」になり、処理が止まる (タスクマネージャーに python/claude が残らない)。(3) アップロードした PDF と、すでにできていた出力・翻訳の途中経過は残り、「この段落だけ再翻訳する」(中止後は続きから) で、選び直さずに再開できる。「削除」は、完了・失敗したジョブをファイルごと消すボタンです。
- 新しいファイルを開始して前回のジョブを置き換えるとき (実行中なら確認あり) は、前回の PDF・出力は削除されます。

構成の整理の採用状態は役割変更の件数だけで決めず、段落結合・記号対応の採用も含めて表示します。キャッシュを使った再実行でも不採用の件数を保持します。開始直後の中止と子プロセス起動を同期し、中止が完了するまで再試行の開始を待つため、遅れた中止が再試行を止めることはありません。

### 翻訳の補助 (assist, M14)

- 構成の整理とは別に、Claude または Codex が **用語集の点検** (題名・要旨 (最大 900 文字)・用語集を送る) と、**検証に通らず英語のまま残った段落の補正** (その段落の原文と訳文を送る、最大 2 回) を行います。この送信内容は、初回設定の同意文と、「翻訳を開始」の下の注意に書いてあります。既存の利用者にも再度の同意を求めます (`CONSENT_VERSION` 3)。
- 「出力」の下の **「Claudeに翻訳の補助をさせない」**（Codex版では「Codexに翻訳の補助をさせない」）にチェックすると、`--no-assist` を付けて実行します (補助だけを止め、構成の整理は変わりません)。既定はチェックなし (補助あり)。Codex版もCLI/Web起動時に補助を登録します。
- 結果欄に 1 行で「Claudeの補助: 用語集の修正 16件、問題段落の補正 3/4件採用」(`render_report.json` の `assist`) を表示します。スキップされたときは「(スキップ: 理由)」、止めたときは「使いませんでした」を表示します。
