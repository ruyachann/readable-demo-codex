# Readable代替 Codex版: 英語PDF -> 日本語PDF

このリポジトリは共有開発フォルダから移行したCodex版です。`config.toml` の既定は `structure.provider = "codex"` で、通常の `翻訳アプリ.bat` と `python -m readable` もCodex CLIを使います。主翻訳はGemini API、構造補正と用語集点検・失敗段落の翻訳補助は契約ログインしたCodex CLIです。

移行内容・検証・既知の残件は [docs/MIGRATION.md](docs/MIGRATION.md) を参照してください。個人PDF・認証情報・作業キャッシュ・配布生成物はGitに含めません。

英語の論文PDFを入力すると、図・表・数式・レイアウトを保ったまま、本文を日本語にしたPDFを出力します。

- `<name>_ja.pdf` : 日本語版 (原文の文字を消して、同じ位置に日本語を流し込む。図・表・数式・リンクはそのまま)
- `<name>_dual.pdf` : 交互版 (英 p1 → 日 p1 → 英 p2 → 日 p2 …。しおり・リンクも維持)

翻訳は Gemini API (無料枠を想定)、文書構造の補正は Claude Code または Codex CLI が行います。Web画面では構造補正を必ず試み、使えない場合は理由を表示し、承認後だけ簡易解析で続けます。

紹介・配布サイト: (URL 未定。決まり次第ここに記載します。ソースは `website/` にあります)
**AI のアカウントは利用者ご自身のもの** (Gemini API キー / Claude CodeまたはCodex CLIの契約ログイン) を使います。構造補正はAPI認証へ暗黙で切り替えません。
紹介・配布ページでClaude版／Codex版を選べます。PDF処理は共通で、構造補正の提供元と既定設定が異なります。Codex版は [docs/CODEX.md](docs/CODEX.md) を参照してください。

使い方は 3 通りあります (おすすめは A):

- **A. `翻訳アプリ.bat`** — ブラウザの画面に PDF をドラッグ&ドロップ (初回設定画面つき)
- **B. `翻訳する.bat`** — bat に PDF をドラッグ&ドロップ (PDF と同じフォルダに出力)
- **C. コマンドライン** — `python -m readable <in.pdf>`

インストール手順 (Python の導入から) は [docs/INSTALL.md](docs/INSTALL.md) を参照してください。

## プライバシーの注意 (必ずお読みください)

- **Gemini API の無料枠では、入力と出力が Google のモデル改善 (学習) に使われる可能性があります。**
  未公開論文・機密文書・個人情報を含む PDF は、無料枠で翻訳しないでください (有料枠は学習に使われませんが、利用規約を確認してください)。
- **構造解析では、各段落の抜粋 (先頭・末尾の数十文字) と図表の周辺情報を、Claude版ではAnthropic、Codex版ではOpenAIへ送ります**。参考文献は送りません。
- **翻訳の補助 (assist、既定でオン) では、さらに次を送ります (全文の校正はしません)**: (1) 用語集の点検: 論文の題名・要旨 (先頭 900 字まで) と、Gemini が作った用語集。(2) 問題段落の補正: 検証に通らず英語のまま残った段落だけの原文 (と、その段落に出る用語集の語)。1 論文あたり最大 3 回 (構造解析と合わせて 4 回: `[assist] max_calls_per_doc`)。送りたくない場合は `--no-assist` (補助だけ止める)、または `--no-claude` / `--no-structure` (構造解析も補助も止める) を付けてください。補助の呼び出し回数・採用/却下の件数は、ログと `render_report.json` の `assist` に記録されます。
  送りたくない場合は `--no-structure` (旧 `--no-claude` も可) を付けてください (Web画面では常にオンで、使えないときだけ理由を見せて「構成の整理なしで続けますか?」と確認します)。簡易解析だけで動きます。
- どちらも実行時に警告を表示します (Web アプリは初回に同意を求めます)。
- **Gemini API キーの置き場所**:
  - コマンドライン・`翻訳する.bat`: 環境変数 `GEMINI_API_KEY` だけを使います (ファイルには保存しません)。
  - `翻訳アプリ.bat` (Web 画面): 画面で登録したキーを `%APPDATA%\ReadableJP\secrets.json` に保存します (現在のユーザーだけが読めるよう権限を制限)。
    環境変数 `GEMINI_API_KEY` があればそちらが優先されます。画面の「削除」でファイルから消せます (環境変数は残ります)。
    アプリのフォルダを削除しても、このファイルは残ります。アンインストール時は `%APPDATA%\ReadableJP` も削除してください。
  - Web 画面で登録したキーは、コマンドライン・`翻訳する.bat` からは使われません。

## 必要環境

- Windows 10/11 (日本語フォントとして `C:\Windows\Fonts` の游明朝 `yumin.ttf` / 游ゴシック `YuGoth*.ttc` / メイリオ `meiryo.ttc` を使用)
- Python 3.11 以上 (`python --version` で確認)
- 日本語フォント (游明朝・游ゴシック・メイリオのどれか。無い環境は `config.toml` の `[fonts]` に `.ttf`/`.ttc` のパスを指定。無いと終了コード 11)
- Gemini API キー (無料: <https://aistudio.google.com/apikey>)
- 構造補正: Claude版はClaude Code、Codex版はCodex CLI (ご自身の契約アカウントでログイン済み)。段落の役割・段またぎの結合を補正します。使えない場合、Web画面では理由と続行の確認を表示します。

## 初回セットアップ

1. **`setup.bat` をダブルクリック** (このフォルダ内の `.venv` にライブラリを入れます。フォルダの外は変更しません)。
   bat を使わない場合は `pip install -r requirements.txt` でも構いません。
2. Gemini API キーを用意 (無料: <https://aistudio.google.com/apikey>)。
   - `翻訳アプリ.bat` を使う場合: 初回の設定画面で登録します (接続テストつき)。
   - `翻訳する.bat`・コマンドラインを使う場合: 環境変数に設定します (コマンドプロンプト。**設定後は新しいウィンドウを開き直す**)

     ```
     setx GEMINI_API_KEY "ここにキー"
     ```

     (PowerShell で一時的に使うだけなら `$env:GEMINI_API_KEY="ここにキー"`。キーは他人に見せない)
3. Claude版はClaude Codeを導入して `/login`、Codex版はCodex CLIを導入して `codex login` で契約アカウントにログインします。Codex版の詳細は [docs/CODEX.md](docs/CODEX.md) を参照してください。操作画面では構造補正を常に使い、使えない場合だけ構造補正なしで続けるか確認します。

## 使い方

### A. `翻訳アプリ.bat` (ブラウザで操作・おすすめ)

`翻訳アプリ.bat` をダブルクリックするとブラウザが開きます。このリポジトリではCodex版が起動します。`翻訳アプリCodex.bat` でも起動できます。初回は設定画面 (Python・ライブラリ・日本語フォント・Gemini キー・選んだCLIの確認と、送信先への同意) が出ます。

PDF を 1 つドラッグ&ドロップ (または選択) すると、ファイル名・ページ数・サイズを表示します。出力形式を選んで **「翻訳を開始」** を押すと変換が始まり、完了後に日本語版・交互対訳版をダウンロードでき、PDF のプレビューも新しいタブで開けます。

- 出力 (日本語版 / 交互対訳版 / 両方) を選べます。構成の整理 (Claude / Codex) は常にオンです。使えないとき (未ログイン・未インストール・API キー検出) は、「翻訳を開始」を押した時に理由と直し方を表示し、同意した場合だけ構成の整理なしで続けます。途中でスキップされた場合は、結果欄に「構成の整理は行われませんでした: 理由」と表示します。
- 一部の段落が英語のまま残った (終了コード 12)・日次上限 (7)・API の回復不能なエラー (9) のときは、結果欄に **「この段落だけ再翻訳する」** ボタンが出ます。サーバー側に残した同じ PDF を `--retry-failed` で再実行するので、ファイルの選び直しは不要です。
- 進捗 (抽出 → 構造解析 → 翻訳 → PDF 生成) とログ末尾が表示され、失敗時は終了コードに応じた日本語の説明が出ます。
- **処理は 1 ファイルずつ、結果は最新の 1 件だけ**保持します。新しい翻訳を始めると前回の PDF は削除されます (必要ならダウンロードしてから)。翻訳中に別のファイルを入れると「中止して新しく始めますか?」と確認します。アプリを終了すると前回の結果は消えます。
- 翻訳の途中経過 (キャッシュ) は `work/` に、最近使った 3 文書ぶんだけ残します (日次上限で止まった文書は、続きから再開できるよう消しません)。
- **PC への影響は最小**です。標準ライブラリだけで動き、常駐・レジストリ変更・管理者権限は不要です。127.0.0.1 だけで待ち受けるため外部から接続できません。**bat のウィンドウを閉じると完全に終了**します。
- 起動ごとに変わるトークン付き URL で開きます。ブラウザのタブを閉じてしまったら、bat を閉じて起動し直してください。
- サーバーを立てる必要はありません (利用者ごとに自分の PC で動かします)。公開サーバとしての利用は想定していません。API 仕様は [docs/API.md](docs/API.md)。

### B. `翻訳する.bat`

英語のPDFを **`翻訳する.bat` にドラッグ&ドロップ** します。複数ファイルを同時にドロップしても構いません。
PDFと**同じフォルダ**に `<元の名前>_ja.pdf` と `<元の名前>_dual.pdf` が出力され、終了時に結果 (成功・失敗の件数) を表示して一時停止します。
日本語・空白・括弧を含むパスでも動きます。1 本あたり数分かかります (Gemini の無料枠は毎分 5 リクエストまで)。

### C. コマンドライン

```
python -m readable <in.pdf> [--out DIR] [--mode ja|dual|both] [--translator gemini|dummy] [--no-claude]
                            [--work-dir DIR] [--retry-failed] [--ignore-quota-state] [--config FILE]
```

| オプション | 既定 | 説明 |
|---|---|---|
| `--out` | `out` | 出力先 |
| `--mode` | `both` | `ja` 日本語版のみ / `dual` 交互版のみ / `both` |
| `--translator` | `gemini` | `gemini` は Gemini 翻訳。`dummy` はレイアウト確認用のダミー訳 (API 不要) |
| `--no-claude` | - | Claude (`claude -p`) による構造解析を使わない (CLI が無い/失敗のときも自動でヒューリスティックに戻る) |
| `--no-structure` | - | Claude/Codexの構造解析を使わない (`--no-claude`の共通別名) |
| `--structure-provider` | 設定値 | 構造補正を `claude / codex / none` から指定 |
| `--work-dir` | `work` (このフォルダ直下) | 中間成果物の置き場 |
| `--retry-failed` | - | 前回の実行で翻訳に失敗した段落も再送する (既定は再送しない) |
| `--ignore-quota-state` | - | 保存された日次上限の状態 (`work/.quota_state.json`) を無視する (課金を有効にした直後など) |

## 出力

| ファイル | 内容 |
|---|---|
| `<name>_ja.pdf` | 日本語版 |
| `<name>_dual.pdf` | 交互版 (英語ページの次に日本語ページ) |
| `work/<name>-<内容ハッシュ12桁>/` | 中間成果物: `doc.json` (抽出結果), `translation_cache.json` (翻訳キャッシュ), `translations.json` (訳文), `glossary.json` (用語集), `render_report.json` (縮小・余白・段階), `gemini_stats.json` (リクエスト数など) |

見た目の方針: 本文・キャプション・脚注など役割ごとに文書全体で文字サイズと行間を揃え (原文の最頻サイズと行送り)、収まらない段落だけを少しずつ縮小します。
原文で字下げされた段落は 1 字下げ。段落の間隔は原文に合わせ、日本語の長さに応じて後続の段落が上下に詰まります。
「23.58歳 ± 3.36歳」のように記号・数値に接する空白は半角のまま (両端揃えで引き伸ばされません)。

## 無料枠の注意と、日次上限に達したときの再開方法

- 無料枠には**毎分の上限 (既定 5 リクエスト/分で制御)** と**1 日の上限**があります。1 日の上限に達すると終了コード 7 で止まり、
  それまでの翻訳は `work/.../translation_cache.json` に保存されます。
- **再開方法: 翌日 (日次上限は太平洋時間の 0 時 = 日本時間の 16 時 (夏時間) / 17 時 (冬時間) にリセット) に、同じ PDF をもう一度処理するだけ**です (bat に再ドロップ、または同じコマンドを再実行)。
  翻訳済みの段落は再送されず、続きから再開します。
- 上限に達したモデルと解除時刻は `work/.quota_state.json` に保存され、期限までそのモデルへの無駄なリクエストを避けます
  (API キーごとに別管理。キーを変えた・課金を有効にした場合は自動で別扱い、または `--ignore-quota-state`)。
- 1 論文 (10〜12 ページ) で、翻訳 約 10 + 用語集 1 + 見直し数リクエスト程度です。複数の論文を連続で処理すると 1 日の枠を超えることがあります。
- 同時に複数のプロセスを走らせないでください (毎分の上限が共有されません)。1 本ずつ処理します (bat は順番に処理します)。

## キャッシュの再利用 (work ディレクトリ)

`work/<名前>-<ファイル内容の sha256 先頭 12 桁>/` に中間成果物が保存されます。名前は **PDF の内容** で決まるので、PDF を移動・コピー・改名しても、
同じ内容なら同じキャッシュ (翻訳・用語集・構造解析) が使われ、再翻訳されません。内容が 1 バイトでも違えば別の work になります。
(以前のバージョンの work ディレクトリ (パスのハッシュ 6 桁) は引き継がれません。必要なければ削除して構いません。)
キャッシュの鍵は 段落の原文・役割 (role)・モデル・プロンプト・その段落に出る用語です。用語集を変えると、その用語を含む段落だけが再翻訳されます。

429 のうち、日次上限と明確に識別できるもの (quota の識別子に PerDay) だけを日次上限として扱い、翌日まで状態を保存します。識別子の無い 429 は未知の上限として待って再試行し、それでも駄目なら終了コード 9 です。

日次上限のとき、翻訳 (flash-lite) が上限なら終了コード 7 で止まります。用語集・選択的な再翻訳に使う flash が上限のときは、自動で flash-lite に切り替えて続行します
(切り替えた分は訳文が少し変わることがあります)。上限の記録は `work/.quota_state.json` (API キーごと) です。

## 対応する PDF と、対応しないもの

| | 状態 |
|---|---|
| 1〜2 段組の英語論文 (MDPI・Wiley/JSR・IEEE 風・arXiv/LaTeX 風・Elsevier 風) | 対応 (数式・図・表・リンク・しおりを保持) |
| 表の本体 | **英語のまま** (表の用語は本文に英語を各ページの初出だけ併記する。和訳のホバー注釈は既定では付けない。後述) |
| 図の中の文字 (画像) | 英語のまま。ベクタ図の小さな文字・等幅フォントのコード・疑似コード (`1:` `2:` の連番) は翻訳しない |
| **スキャン + OCR 文字層つき PDF** (古い論文のスキャンなど。文字は画像で、見えない OCR テキストが重なっているもの) | **対応** (翻訳した行の英語を紙の色で隠して日本語を載せる。図は触らない。OCR の誤認識は文脈から推定して訳す。仕上がりは通常の PDF より粗くなることがある) |
| 完全なスキャン PDF (テキスト層なし) | 対象外 (OCR 未対応。終了コード 6) |
| スライド PDF | **未対応** (箇条書きが 1 段落に結合されるなど、論文向けの前提と合いません) |
| PDF 以外 (`.txt` `.epub` など) | 終了コード 5 |
| パスワード付き PDF | 終了コード 4 |

## 表の用語と本文の対応づけ

表は英語のままなので、本文を訳すと「本文のどの語が表のどの語か」が分からなくなります。そこで:

- **本文に英語を併記**: 表のカテゴリ名・項目名・列見出し・略語つきの語 (「Locomotion (Lo)」など)・図表キャプション中の英語の用語を、翻訳前に集めて用語集に
  `keep_en` つきで入れます (数値・日付・単位は含めません)。本文では、それらを「移動 (Locomotion, Lo)」「活動 (Active)」の形にします (**英語の併記は各ページで初出の 1 回だけ**。同じページの 2 回目以降は日本語だけ。訳す段階では毎回併記させ、描画のときに 2 回目以降の括弧を外します。`[table_terms] gloss_first_only = false` で毎回併記)。
  併記されない場合は検証で再送し、それでも駄目なら訳は採用して警告だけ出します (原文には戻しません)。
- **色づけ**: 既定は色なし・下線なしです。`[table_terms] color = "#1a3d8f"` のように指定すると、本文の「(English)」部分を指定色 + 下線にします。
- **ホバー注釈 (既定はオフ。`[table_terms] annotations = true` で付ける)**: オフのときは表のセル・図の中の文字を訳さず、Gemini のリクエストも増えません。オンにすると、日本語版 (と交互版の日本語ページ) の表のセルと**図の中の文字**に、日本語訳を PDF 注釈 (ハイライト注釈の Contents) として付けます。図表の中の文字は翻訳して差し替えず、すべて英語のままで、すべて同じ形の注釈になります。見た目は変わりません
  (既定の `annotation_style = "invisible"` は完全に透明で、見える印は一切ありません。同じ原文の図の軸ラベルは 1 回だけ訳します)。交互版の英語ページには何も付きません。セルの翻訳には Gemini のリクエストが少し増えます。
  **表示のされ方は PDF ビューアで異なります**: Adobe Acrobat ではセルにカーソルを置くとポップアップで表示されます。Chrome・Edge の内蔵ビューアは、ハイライト注釈のホバー表示に対応していないため、
  表示されないか、注釈パネルでのみ読めます。付箋アイコン方式 (`annotation_style = "text"`) にすると、アイコンがセルの角に見え、クリックで内容を読めるビューアが増えます。
- 設定: `[table_terms] keep_en / color / annotations / annotation_style (invisible | highlight | text) / max_cells / max_figure_cells / gloss_first_only`。

### Claude を使う条件 (API 課金を避けるため)

この版は **Claude の契約 (サブスクリプション) のログインだけ** を使い、Claude API (従量課金) は使いません。次のとき、構造解析は警告を出してスキップし、ヒューリスティックで続行します (翻訳は止まりません):

- 環境変数に `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_BASE_URL` (ゲートウェイ) / `CLAUDE_CODE_USE_BEDROCK`・`VERTEX` などがある (外して呼ぶのではなく、呼ばないことで課金を避けます)。
- `claude auth status` が、契約ログイン (`claude.ai`) ではない・未ログイン・判定できない。

開発用に、ゲートウェイ経由で使いたいときだけ `--allow-claude-gateway` (または `[claude] allow_gateway = true`、既定 OFF)。この場合も API キーは子プロセスに渡しません。

## 用語集と表記ゆれ

翻訳前に Gemini が論文から用語集 (英→日) を作り、訳語を統一します。生物名・装置名・手法名などの基本名詞も含みます。
翻訳後、用語集の訳語と異なる表記 (ひらがな⇔カタカナ、長音の有無、用語集に書かれた別表記) を用語集の表記へ自動で寄せます (用語集に載った語だけが対象)。

### `glossary_override.json` で用語集を差し替える

`work/<name>-<内容ハッシュ12桁>/glossary_override.json` を置くと、自動の用語集の代わりに使われます (API は呼びません。空 `[]` は「用語集なし」)。
実際のパスは翻訳開始時に表示されます。形式は次のどちらか:

```json
[{"en": "otter", "ja": "カワウソ", "variants": ["川獺"]}, {"en": "headband", "ja": "ヘッドバンド"}]
```

```json
{"otter": "カワウソ", "headband": "ヘッドバンド"}
```

`variants` は訳文に現れたら `ja` に統一したい別表記です。変更した用語を含む段落だけが再翻訳されます (用語集全体ではなく、その段落に出る語のハッシュがキャッシュキーです)。

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | 想定外のエラー (概要を 1 行で表示し、詳細 (traceback) を `work/last_error.log` に保存)。それまでの翻訳はキャッシュに保存済み |
| 2 | 入力が見つからない |
| 3 | 翻訳器を使えない (`GEMINI_API_KEY` 未設定など) |
| 4 | パスワード付き PDF |
| 5 | PDF として開けない (PDF 以外のファイル `.txt` など・壊れたファイル・フォルダを含む) |
| 6 | 翻訳対象のテキストが無い (スキャン PDF など。OCR は対象外。一部ページだけ無い場合は警告してそのページは原文のまま) |
| 7 | Gemini の日次上限 (翌日に再実行で続きから) |
| 8 | 設定・権限の誤り (API キー不正 401/403、モデル名誤り 404、不正なリクエスト 400)。再試行しても直らない |
| 9 | API の回復不能なエラー (5xx・タイムアウトが 3 回再試行しても直らない、毎分の上限が続く)。時間をおいて再実行。開発用の予算上限 (環境変数 `READABLE_GEMINI_MAX_REQUESTS` に達した。送らずに止まり、再実行で続きから) も 9 |
| 10 | 入力データの誤り (`charmap.json` が壊れている等) |
| 11 | 日本語フォントが見つからない (翻訳を始める前に確認するので、API 枠は消費しない)。`config.toml` の `[fonts]` にフォントのパスを指定 |
| 12 | **一部の段落だけ翻訳できず原文のまま** (PDF は出力される)。応答が空・安全フィルタなどで 1 段落が通らなかった場合。件数を表示し、`--retry-failed` で、その段落だけ再翻訳する |
| 130 | Ctrl-C で中断 (翻訳は保存済みで、再実行で再開) |

7〜9・12・130 では、それまでに検証を通った翻訳はキャッシュに保存済みです。**API エラーのときに、原文のままの PDF が成功として出力されることはありません**。
バッチ (3 ページ分) の中で 1 段落だけが応答不能になったときは、バッチを半分ずつに分けて送り直し、原因の段落 1 つだけを失敗として記録します (他の段落は巻き込まれません)。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `Python が見つかりません` (bat) | Python 3.11 以上をインストール (「Add python.exe to PATH」にチェック)。Microsoft Store の空のエイリアスだけの場合も同様 |
| `必要なライブラリがインストールされていません` | `setup.bat` を実行 (または `pip install -r requirements.txt`) |
| 終了コード 3 / `GEMINI_API_KEY が設定されていません` | `setx GEMINI_API_KEY "キー"` のあと**新しいウィンドウ**で実行 (bat も開き直す) |
| 終了コード 8 | キーが違う/無効 (401, 403)、モデル名の誤り (404: `config.toml` の `[gemini] translate_model`)、利用地域外。キーを確認して再実行 |
| 終了コード 7 / 日次上限 | 翌日に同じ PDF を再実行 (上記)。急ぐときは別のプロジェクトの API キーを使うか、課金を有効にして `--ignore-quota-state` |
| 終了コード 9 | Gemini 側の混雑・ネットワーク。しばらくして再実行 (続きから再開) |
| 日本語が文字化けする (コンソール) | `chcp 65001` と `set PYTHONIOENCODING=utf-8` (bat は自動で設定) |
| 一部の段落が英語のまま | 検証に通らなかった段落です (警告に id と理由が出ます)。`--retry-failed` で再試行。直らなければ `glossary_override.json` に用語を足す |
| 訳語が揺れる/気に入らない | `glossary_override.json` で訳語を固定して再実行 (影響する段落だけ再翻訳) |
| キャッシュが壊れた | 自動で `.bak` に退避して空から始めます (警告表示)。`work/<name>-.../` を削除すれば最初からやり直し |
| Claude の構造解析がスキップされた | Claude Code が無い・未ログイン・失敗しただけで、警告後にヒューリスティックで続行します。`--no-claude` で明示的に無効化可能 |
| 縮小が目立つ・はみ出す | `config.toml` の `[render]` (`min_scale`, `line_height_min/max`, `uniform_style`)。結果は `render_report.json` |
| スキャン PDF | テキスト層が無いと対象外です (OCR 未対応) |

## 設定 (`config.toml`)

`[gemini]` モデル・RPM・`timeout` (リクエストの待ち時間, 秒)・バッチ・`refine` (全段落の見直し, 既定 OFF) / `[claude]` / `[fonts]` / `[extract]` / `[render]` (基準サイズ・行間・字下げ) / `[paths] work_dir`。
フォントの候補は `[fonts]` で変更できます (可変フォントは使いません)。

## リンク・しおり

- 日本語版: 翻訳領域の外のリンクは維持。翻訳領域内の外部 URL は訳文の `<a href>` から再作成。翻訳領域内の内部リンク (引用 [n] など) は失われ、件数を `render_report.json` と CLI 出力に記録。
- 交互版: 英語ページのリンク・しおりは原文と同数。日本語ページのリンクは日本語ページを指します。

## 前提・過適合の注意

`LABELS` (JSR/MDPI のラベル)、`ARTICLE_TYPE_RE`、左サイドバー判定、`short_line_factor` / `para_max_pitch` の単一値は 2 論文に合わせた値です (Claude の補正で吸収する前提)。
`config.toml` の `translate_tables = true` で表本体も翻訳対象にできます (既定は英語のまま)。

## 開発

**Gemini の予算上限 (開発・検証専用)**: 環境変数 `READABLE_GEMINI_MAX_REQUESTS` に整数を入れると、そのプロセスが Gemini へ実際に送るリクエスト数をその数までに制限します。次のリクエストが上限を超えるときは**送らずに**止まり、翻訳済みの分はキャッシュに保存して終了コード 9 で終わります (「開発用の予算上限 (READABLE_GEMINI_MAX_REQUESTS=N) に達したため…送信済み: n 回」と表示。上限を外して再実行すれば続きから再開します)。開発者が実機で検証するときの超過防止用で、**利用者の通常の実行では設定しません**。

**処理時間**: 12 ページの論文のおおよその時間は、リクエスト数 (用語集 1 + 翻訳のバッチ + 再送) × 12 秒 (`rpm = 5` のとき) が目安です。`[gemini] pages_per_batch / max_chars` を大きくするとリクエストが減り、`workers` (既定 3) で独立なバッチを同時に送れます。**無料枠の実際の RPM は AI Studio (https://aistudio.google.com/rate-limit) で確認し、`config.toml` の `rpm` を上げてください** (上げすぎると 429 になります)。段階別の時間 (extract / structure / glossary / translate / render) は `render_report.json` の `stage_times` に記録されます。

### 固定訳 (`glossary_fixed.toml`)

どの論文でも優先したい訳語 (統計・神経科学・VR/HCI の用語など。例: inferential statistics → 推測統計) は、プロジェクト直下の `glossary_fixed.toml` に書きます。
論文ごとに Gemini が作る用語集より優先され、**その論文の本文に出てきた語だけ**が翻訳に渡されます (`[variants]` に書いた別表記は翻訳後に統一されます)。
論文ごとの `glossary_override.json` があるときは、そちらが最終で、この表は使われません。
複数語の固定訳 (correct rejection → 正棄却 など) が使われず、英語が日本語の中に残った訳 (例: 「CR(正 rejection)」) は検出して、その unit だけ再送します (再送でも直らなければ訳は採用し警告のみ)。
