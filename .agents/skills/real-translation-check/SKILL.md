# 実翻訳と確認の手順

## 1. 始める前に予算を数える (省略しない)
1. 対象 PDF ごとに `work/` に同じ内容ハッシュのキャッシュがあるか確認する (`readable.cli.work_name` と同じ規則: `<stem>-<sha256先頭12桁>`)
2. 予定リクエスト数を見積もる: 未キャッシュなら 1 論文 ≈ ページ数 ÷ バッチページ数 + 用語集 1 + 表セル 1 + 再送の余裕 3。キャッシュがあれば変わった段落分だけ
3. 見積もりと依頼の上限を画面に出す。上限を超えるなら実行せず報告する
4. 日次上限の記録 (`work/.quota_state.json`) と解除時刻 (日本時間 16 時) を確認する

## 2. 実行
- `python -m readable <pdf> --out <依頼の出力先> --mode both` (この開発セッションで Codex を試すときだけ `--allow-Codex-gateway`)
- ユーザーの論文は読み取りのみ。work/out をリポジトリ外に置く指定があれば従う
- 終了コード 12 なら `--retry-failed` を 1 回だけ。7 なら止めて報告
- 各実行後に `gemini_stats.json` のリクエスト数を読み、累計を画面に出す

## 3. 確認
1. 原文と `_ja.pdf` を全ページ PNG (dpi 60〜70) にして見比べる。疑わしい所は dpi 110 で拡大
2. 機械検査: `_ja.pdf` のテキストに `<i>` `{v` `⟦` `&amp;` が無いこと、豆腐が無いこと
3. `render_report.json` の 縮小件数・最小 scale・リンク消失数・scanned_ocr・段階別時間 を読む
4. docs/ACCEPTANCE.md の項目ごとに 合格/不合格/未確認 の表を画面に出す (見ていない項目を合格にしない)

## 4. 報告
- 論文ごと: 終了コード・所要時間・リクエスト数・ACCEPTANCE の表・代表 PNG のパス
- 予算の実績 (見積もりとの差と理由)
